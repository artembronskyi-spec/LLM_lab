# Специфікація: Сервіс каталогу тренувальних вправ

## 1. Схема даних (Exercise)
Запис про вправу містить наступні поля:
- `id` (int, автоінкремент) — унікальний номер вправи.
- `name` (str, обов'язкове) — назва вправи.
- `difficulty` (str, опціональне) — рівень складності: тільки `"початковий"`, `"середній"` або `"високий"`. Якщо не вказано — `null`.
- `equipment` (str, опціональне) — потрібний інвентар (наприклад: `"штанга"`, `"гантелі"`, `"турнік"`, `"без обладнання"`). Якщо не вказано — `null`.

---

## 2. HTTP API Маршрути

### GET /exercises
Отримати список усіх збережених вправ.
- **Успіх (200 OK):** повертає масив JSON з об'єктами вправ.

### POST /exercises
Ручне створення вправи без залучення LLM.
- **Тіло запиту:** `{"name": "...", "difficulty": "...", "equipment": "..."}`
- **Успіх (201 Created):** повертає створену вправу з id.
- **Помилка валідації (422 Unprocessable Entity):** якщо поле `name` порожнє або `difficulty` не зі списку дозволених. Запис у базу НЕ додається.

### POST /exercises/from-text
Створення вправи з короткого тексту через LLM.
- **Тіло запиту:** `{"text": "..."}`
- **Успіх (201 Created):** повертає створену та збережену вправу.
- **Відхилення (422 Unprocessable Entity):**
  - Текст не містить назви вправи (`status: "needs_clarification"`).
  - LLM повернула некоректні дані або галюцинацію (`status: "rejected"`).
  - Запис у базу НЕ додається, список вправ не змінюється.
- **Недоступність AI (503 Service Unavailable):** якщо LLM-провайдер недоступний чи повернув помилку мережі. База не змінюється, але ручні ендпоінти залишаються робочими.

---

## 3. Логіка валідації та перевірка галюцинацій

1. **Обов'язковість назви:** Якщо `name` відсутнє у відповіді LLM — відмова.
2. **Перевірка складності:** Поле `difficulty` звіряється зі списком `["початковий", "середній", "високий", None]`. Інші значення відхиляються.
3. **Алгоритм перевірки обладнання (`equipment`):**
   - Якщо `equipment == "без обладнання"` або `None` — дозволено.
   - Якщо вказано конкретний інвентар (наприклад, `"штанга"`), сервіс перевіряє наявність кореня цього слова в початковому тексті користувача (в нижньому регістрі). 
   - Якщо згадки інвентарю в тексті немає — пропозиція вважається галюцинацією та відхиляється.

## 4. Джерела AI для тестів

- **Mock (фіксовані відповіді):** Використовується за замовчуванням у всіх детермінованих тестах та сценаріях ноутбука 2. Забезпечує стабільність перевірок без витрат коштів та залежності від мережі.
- **Live LLM (Ollama / API):** Використовується для окремої перевірки інтеграції (якщо доступно). Якщо виклик недоступний — у звіті фіксується статус `not_run`.
